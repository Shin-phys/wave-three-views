# 波の3つの見方（仮称）

## 1. 概要

生徒が撮影した波の動画と、手描きした作図の連番写真を入力にして、次の3つを連動して見せるアプリ。

| 見方 | 作り方 | 対象 |
|---|---|---|
| y-x図 | 動画の1コマ（時刻を止める） | 実写動画・手描き連番 |
| y-t図 | 1か所の縦の画素列を時間順に並べる（場所を固定する） | 実写動画・手描き連番 |
| ぱらぱら漫画 | 手描きの作図を位置合わせして連続再生する | 手描き連番（定常波など） |

動画は y(x, t) そのものなので、時刻を止めれば y-x図、場所を固定すれば y-t図になる。生徒がつまずきやすい2つの図の対応を、1画面で扱うことがねらいである。

## 2. ねらい

- y-t図は「媒質の1点の履歴」であり、波の形の写真ではないことを体感させる。
- 向かい合う波の合成波を自分で作図し、それが動くことで定常波（節は動かず、腹が大きく振動する）を見出させる。
- 手描きの連番にも同じ道具が使えることを通して、作図と実物の波を同じ見方でつなぐ。

## 3. 決定事項

- 【決定】入力は、生徒が撮影した実物の波の動画と、手描き作図の連番写真とする。シミュレーションを主にはしない。
- 【決定】保険として、サンプル動画（シミュレーション）を同梱する。
- 【決定】y-x図、y-t図、ぱらぱら漫画（定常波）を1つのアプリに統合する。

- 【決定】技術構成は、`src/` を編集してビルドスクリプトで単一の `index.html` を生成する構成とする（WAVE-N-08）。
- 【決定】動画は読み込み時に全コマを縮小して保存し、以後の処理はそこから行う（WAVE-N-10）。
- 【決定】y-t図の見せ方は5段階すべてを初版に入れる。段階2はペン先が右へ進む方式とする（`02-yt-animation.md`）。
- 【決定】ぱらぱら漫画は T/8 の8コマ、横1目盛り = λ/8、振幅 = 縦7目盛り。用紙はアプリが生成し、ArUco マーカーの ID でコマ番号を表す（`03-flipbook.md`）。
- 【決定】サンプルはアプリ内で生成し、実写のお手本だけ動画ファイルで置く（`01-requirements.md` §1.1）。
- 【決定】x-t図は初版に入れない。

## 4. 当面の範囲外

- x-t図（横の線を時間順に積む図）は発展扱いとする（WAVE-F-40）。
- 弦や音叉のような速い振動は対象外。30 fps の動画で扱えるのは数Hzまでである。

## 6. 引き継ぎ（次にすること）

決めること：

1. 撮影をアプリ内で行うか、標準カメラで撮ってから読み込むか（WAVE-Q-02）

実機・実物で確かめること：

1. 用紙の試し刷り：方眼の寸法（横 15 mm × 縦 5 mm 案）が A4 横に収まり描きやすいか（`03-flipbook.md` §4.1）
2. 赤の抽出：試し刷りした用紙に赤ペンで描いて撮影し、照明を変えて確かめる（WAVE-Q-10）
3. マーカー：検出ライブラリと辞書の種類、手持ち撮影での検出率（`03-flipbook.md` §6.1）
4. 動画：iPhone の MOV・スロー動画、Windows での HEVC 再生、フレームレートの推定（WAVE-Q-09）
5. 全コマ保存のメモリ量がスマホで収まるか（WAVE-N-11）
6. 実写の波で読み取りやすい y-t図が得られる撮影条件（WAVE-Q-12）

上の確認がすんで WAVE-Q-02 が決まれば、仕様を 1.0 として実装に着手できる。
